# Changelog

## v0.1.18 — 2026-11-02

- Белый список стран (`AllowedCountry`, таблица `allowed_countries`): если в нём есть действующие записи, посетителям
  из других стран — 403 с объяснением. Проверка — после белого списка IP (он главнее) и до блокировок и правил
  сканеров. Страна размещения сайта (`BOT_GUARD_HOME_COUNTRY` или страна часового пояса приложения) добавляется
  автоматически на 10 лет, если действующей записи о ней нет. Без базы GeoLite2 ограничения нет.
- Команда `bot-guard:allow-country {code?} {--days=} {--reason=}`, политика `AllowedCountryPolicy`.
- Миграция: таблица `allowed_countries`.

## v0.1.17 — 2026-11-02

- `bot-guard:geoip-update`: архив MaxMind распаковывается потоком, кусками по 1 МБ — PharData разворачивал
  настоящую базу (~60 МБ) в память и падал на memory_limit 128 МБ.

## v0.1.16 — 2026-11-02

- Страна и город заблокированного IP: определяются при блокировке по локальной базе MaxMind GeoLite2-City
  (`maxmind-db/reader`, без обращения к сети) и хранятся в колонках `country_code`, `country`, `city`.
  Нет базы — блокировка работает как обычно. `BannedIp::location()`, `BannedIp::flag()`.
- Команды `bot-guard:geoip-update` (скачать базу с учётной записью MaxMind и заполнить пустые записи) и
  `bot-guard:geoip-fill {--all}`. Настройки — `geoip` в конфиге.
- Миграция: колонки `country_code`, `country`, `city` в `banned_ips`.

## v0.1.15 — 2026-10-30

- Правила тела запроса проверяют и multipart/form-data: PHP не отдаёт его сырое тело, поэтому пробы React2Shell
  multipart-формой проходили мимо.

## v0.1.13 – v0.1.14 — 2026-10-29

## v0.1.12 — 2026-10-28

  скриптовые клиенты Python `python-httpx`, `aiohttp` (рядом с `python-requests`).

## v0.1.11 — 2026-10-27

- Правило сканеров «RCE в теле запроса без маршрута» распознаёт обфусцированные пробы React2Shell: тело проверяется
  и после раскодирования (URL-кодирование, `\u005f` / `\x5f` любой глубины); новые признаки — поля Server Action
  Next.js (`$ACTION_REF_0`, `$ACTION_0:0`, `$ACTION_ID_…`), ключи протокола RSC (`_response`, `_prefix`, `resolved_model`),
  `__proto__`, косвенный `(0,eval)`. Тест на телах настоящих проб (`tests/Fixtures/react2shell-bodies.json`).

## v0.1.10 — 2026-10-26

## v0.1.9 — 2026-10-25

- Белый список (`allowed_ips`, модель `AllowedIp`): подсеть IP, которую фильтр не трогает до `allowed_until`
  (пусто — навсегда) — запросы не отклоняются, не проверяются правилами сканеров, не ведут к автоблокировке.
- `AllowedIp::fromBan($ban, $days, $reason)` — перенос из заблокированных: ссылка `banned_ip_id` и снимок
  блокировки `banned_snapshot` (остаются и после удаления блокировки), блокировка завершается.
- Сроки на выбор — `allow_durations` (по умолчанию 1, 7, 30 дней и навсегда), `AllowedIp::durationOptions()`.
- Команда `bot-guard:allow {ip} --days= --reason=`; политика `AllowedIpPolicy` (тот же gate `admin_gate`).
- Миграция: таблица `allowed_ips`.

## v0.1.8 — 2026-10-25

- Правило сканеров: нагрузка удалённого выполнения кода в теле не-GET запроса к адресу без маршрута —
  проба React Server Components / Next.js («React2Shell»: `$1:constructor:constructor`, `:__proto__:then`),
  `process.mainModule`, `child_process`. Существующие маршруты (формы сайта, Livewire, API) не проверяются:
  в их полях пользователи законно пишут любой текст. Дополнительные правила — `rules.bodies`.
- Правило сканеров: User-Agent `fasthttp` (скриптовый HTTP-клиент на Go), рядом с `python-requests`.

## v0.1.7 — 2026-10-24

- Повтором считается атака подсети не позже `auto_ban_repeat_window_hours` часов (по умолчанию 24) после
  окончания её последней автоблокировки; вернулась позже — счёт начинается заново, с `auto_ban_hours`.
  `null` — повтором считается атака в любое время (как в v0.1.5–v0.1.6).

## v0.1.6 — 2026-10-24

- `auto_ban_multiplier` по умолчанию 2 вместо 30: повторные автоблокировки подсети — 24 ч → 2 дня → 4 дня → 8 дней…

## v0.1.5 — 2026-10-24

- Повторные атаки подсети: каждая следующая автоблокировка той же подсети (в том числе с другого IP,
  после истечения прежней блокировки) длиннее предыдущей в `auto_ban_multiplier` раз (по умолчанию 30):
  24 ч → 30 дней → 900 дней…, но не больше `auto_ban_max_hours` (по умолчанию 87600 — 10 лет).
  В причине блокировки — номер повтора и срок. `bot-guard:unban` сбрасывает счёт повторов подсети.
- Миграция: в `banned_ips` колонки `network` (подсеть IP) и `ban_count` (номер автоблокировки подсети);
  существующие записи заполняются, автоблокировки считаются первыми.

## v0.1.4 — 2026-10-24

- Правило сканеров: POST на `/livewire/update` (`/livewire-<хэш>/update`) без заголовка `X-Livewire`
  или не JSON — запрос не от Livewire, а скрипт, повторяющий снятый со страницы запрос
  (сам Livewire отвечает на него 404). Такие запросы отсекаются до сессии и маршрутизации,
  пишутся в журнал сканерными и учитываются в автоблокировке.

## v0.1.3 — 2026-10-21

- Правило перебора адресов: `not_found_burst` (5) разных несуществующих страниц с одного IP за
  `not_found_burst_seconds` (10) секунд — сканер, даже если адреса обычные (`/purchases`, `/lots`, `/trades`).
  404 серии в журнале ошибок помечаются сканерными, запросы серии учитываются в автоблокировке.
  Не учитываются: вошедшие пользователи, статические файлы и подзапросы браузера (`Sec-Fetch-Dest`),
  частные IP, поисковые роботы (`not_found_burst_except_user_agents`). `not_found_burst = 0` — выключено.

## v0.1.2 — 2026-10-21

- Правила сканеров: SQL-инъекции по синтаксическим признакам — подбор числа столбцов (`ORDER BY 1-- -`),
  ошибки приведения типов SQL Server (`CONVERT(INT,…)`, `CAST(… AS INT)`), тавтология после кавычки или скобки
  (`' AND 1=1`, `) AND (123=123'`), комментарий сразу после кавычки (`'-- -`), служебные объекты СУБД
  (`information_schema`, `@@version`, `xp_cmdshell`, `pg_sleep`, `extractvalue(`, `updatexml(`).
  Обычный поиск со словами «order by», «select», «and» под правила не попадает.
